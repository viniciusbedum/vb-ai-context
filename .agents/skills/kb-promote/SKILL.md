# Knowledge Base promote

Promotion creates a bridge; it does not move or rewrite Knowledge Base files.

## Workflow

1. Read the requested concept, its source notes, and closely related KB notes.
2. Create one new note in `X01 📥 Inbox/` using the floating-note structure as a starting point.
3. Write a concise seed in the user's own-thinking frame: the idea to examine, why it may matter, open questions, and a next processing step. Do not present source language as the user's belief.
4. Link the inbox note to every KB note that materially supports it and to `[[inbox-index]]`.
5. Update `X01 📥 Inbox/inbox-index.md` with a direct link to the new note.
6. Leave the raw source, curated notes, and KB indexes unchanged. Verify links and report the created relative path.

If the user has not identified a specific concept, present the plausible candidates and wait for a choice because promotion changes the personal knowledge layer. If the user wants a finished permanent note instead, use `$zk-process` after the idea has been evaluated.
